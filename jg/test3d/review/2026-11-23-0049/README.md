# 0049 · v8d.1 색 대비와 창 노출 보정

기준은 v8d `55c40b7`의 `jg/test3d`다. 별도 Blender 렌더 시험판은 수정하지 않았다.

`compare-v8d-v8d1-1920x1080.png`의 왼쪽은 수정 전, 오른쪽은 수정 후다. 위는 평소 업무, 아래는 공격 직후 `mess`다. 각 원본은 1920×1080이며 비교판에는 절반 크기로 배치했다. 원본 캡처에도 이미지 색 보정을 추가하지 않았다.

- HDR 환경광의 재질별 세기를 0.65–0.72에서 0.32로 줄이고 주광을 2.1에서 2.8로 조정했다. 반구광·반사도도 함께 낮춰 밝은 면과 그늘을 구분했다.
- ACES → sRGB 출력 뒤에 대비 1.12, 채도 1.10을 적용한다. 저·중·고화질에 같은 보정을 사용한다.
- 캐릭터 배율 3.4 → 2.6, 책상 배율 2.3 → 1.8, 카메라 각도 28° → 32°. 완두콩 책상은 옆으로 옮겨 눈 가림을 해소했다.
- 변경된 모듈의 캐시 키와 표시 버전을 `8d.1`로 갱신했다.

창 노출은 유리 면을 81×25로 균등 표본화하고, 카메라에서 각 점까지 불투명 메시가 가리는지 raycast로 검사했다. 하단은 아래쪽 12줄이다. 화면 전체 픽셀 면적 비율과는 다르다. 친구뿐 아니라 책장·책상 등 가구의 가림도 포함한다. 캐릭터 화면 높이는 투영된 외곽 상자의 높이다.

검증은 Tutti 관리 브라우저에서 카메라를 열지 않고 수행했다. 별도 임시 QA 서버가 동일한 난수 시드와 0.15초 간격의 애니메이션 시계를 주입하고, 비교 시점까지 중간 렌더만 생략했다. 제품 소스에는 이 계측 코드를 넣지 않았다. `mess`는 양쪽 모두 전투 24.45초, 충돌 68회이며 투척 15회·깍지 총 45회·바주카 8회다. 크기 변화로 투사체·얼룩의 난수 소비 순서는 달라질 수 있으므로 얼룩 무늬 자체의 일치를 주장하지 않는다.

- 기존 `director.test.mjs` 9개 통과.
- 제품 JavaScript 모듈 10개 구문 검사 통과.
- 브라우저에서 `mess` → `hide` → `work` 복귀, 전원 소품 수령 7건 확인.

- 저·중·고화질 모두 렌더 성공. 저화질 1632×918, 중·고화질 1920×1080, 대비·채도 보정 공통 유지.
- 캡처 시 브라우저 오류와 자산 로딩 오류 0건.
- QA 주입 없이 실제 페이지도 별도로 열어 v8d.1, 친구 7명, 고화질 보정값, 자산 로딩 오류 0건과 화면을 확인했다.
