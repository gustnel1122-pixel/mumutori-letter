# 0103 · v8e 경량 렌더, 작은 사무실, 큰 창, 충돌 회피

기준은 v8d.1 `4e09673`이다. 정식 결과 파일은 일감함의 `결과/20261123_0103_jg-v8e-nolag-small-bigwindow_결과.md`에 이 세션이 직접 작성한다.

시험 주소: https://letter.mumutori.com/jg/test3d/?demo=1

- SSAO·bloom·실시간 그림자·전송 유리·HDR 환경맵·HDR 렌더 타깃을 제거했다. 고정 가구는 조명을 정점 색으로 미리 계산해 묶고, 캐릭터·장난감은 Lambert 재질로 단일 렌더한다. 바닥/접지 그림자는 재사용 텍스처다.
- ACES→sRGB 뒤 대비 1.12·채도 1.10을 재질 셰이더에서 적용한다. 전체 화면 후처리 패스가 없고, 모든 화질에서 같은 색 보정을 사용한다.
- 캐릭터 배율 2.6→1.65, 책상 1.8→1.2, 창 16.4×4.9→28.8×8.4. 책장·화분·커피 코너를 옆으로 옮기고 장비 상자는 책상 위에 배치해 통로를 비웠다. 픽셀비는 1을 기준으로 하며 저화질만 0.85배다.
- 정본 몸·모자·잎의 수평 외접 반경, 가구 사각형, 이동 선분 전체의 충돌을 검사한다. A*는 0.4 격자에서 찾고 좁은 길은 0.2로 재탐색한다. 탐색은 프레임당 최대 64개 노드, 목표 2ms씩 나눈다. 완료 전에는 안전한 위치에서 기다린다.
- 양옆 좁은 길은 순서를 정해 지나가며 전투·도망·복귀·평소 방문 모두 같은 충돌 검사를 거친다. 밀고 있는 바주카는 친구와 함께 움직인 뒤 현재 위치로 다시 검사한다. 이동 완료까지 장면 시계가 기다리므로 한 주기의 실제 시간은 명목 36초보다 길 수 있다.
- 준비/던지기/총/바주카/엉망 장면에서 7명 모두 창 쪽을 향한다. 복귀 때는 다시 앞을 본다. 해바라기씨는 발사하지 않는다.

## 60초 실제 시간 FPS

| 화면 크기 | v8d.1 평균 / 1% low | v8e 평균 / 1% low | fast 평균 / 1% low |
| --- | ---: | ---: | ---: |
| 1920x1080 | 78.84 / 31.26 | 140.70 / 42.84 | 23.97 / 18.43 |
| 2000x1200 | 74.42 / 25.22 | 142.50 / 58.00 | 23.97 / 16.60 |

Windows Chrome headless, NVIDIA RTX 3070 / ANGLE D3D11, DPR 1, 단독 프로필을 하나씩 실행했다. 5초 준비 뒤 60초를 실제 시간으로 재며 가상 시계나 렌더 생략을 사용하지 않았다. 3D는 전투 한 주기와 이후 평소 동작을 포함하고 화질은 고정 high다. 1% low는 가장 느린 1% 프레임 간격의 평균을 FPS로 환산했다.

fast는 기존 1280×720 합성과 24fps 영상의 새 프레임만 그리는 구조다. 표의 화면 크기는 표시 크기이며, 3D 렌더 FPS와 fast 합성 FPS의 의미가 다르다. 영상에는 HTTP Range를 지원하는 로컬 서버를 사용했다. **LG 울트라탭·iPad 실기 및 카메라 동시 FPS는 미측정**이다.

창 투영 면적은 화면에 투영된 네 모서리의 사각형 면적이다. 창 노출은 유리 면의 81×25 표본 중 가구·친구가 가리지 않는 비율이며, 하단은 아래 12줄이다. 두 지표는 분모가 다르다. 겹침은 몸의 충돌 반경과 가구의 바닥 차지 영역 기준이며, 앞뒤로 지나갈 때 생기는 화면상의 가림은 가능하다.

세 해상도 각각 공격·숨기·복귀와 이후 평소 60초를 60Hz 합성 시간으로 실행했다. 이 구도/충돌 검증에는 중간 GPU 렌더를 생략했으며, FPS 표의 실제 시간 계측과 별개다. 최종 사진에는 이미지 색 보정을 추가하지 않았다. before/after는 같은 시드지만 객체/행동 변화로 난수 소비가 달라 얼룩 무늬의 일치를 주장하지 않는다.
