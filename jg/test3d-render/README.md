# 진격의 오피스 — 렌더 시험판 ⓑ

실제 매장 채택 전에 ⓐ 실시간 3D와 화질·반응·안정성을 비교하기 위한 별도 경로다. 페이지는 noindex/nofollow다.

- `index.html`: 전용 재생 화면. 시작 버튼을 누를 때만 카메라를 요청한다.
- `compare.html`: 카메라 없이 두 화면을 각각 1920×1080 프레임 안에서 나란히 보여 준다. 동시 재생 FPS는 단독 성능 측정으로 사용하지 않는다.
- `?demo=1`: 카메라 없이 평소 장면 시작.
- `?debug=1`: 합성 FPS·디코딩 누락·감지 시간·가동 시간과 수동 감지/퇴장 시험. 왼쪽 위 5번 탭으로도 연다.
- `?cpu=1`: GPU를 쓸 수 없을 때의 축소 키잉 경로 시험.

S1은 8초 반복이다. 얼굴 크기가 기준에 든 두 번의 감지를 확인하면 S2~S4 연속 영상으로 바꾼다. S2 준비 5초 → S3 공격 12초 → S4 퇴장/빼꼼/복귀 6초다. 손님이 계속 있으면 S4의 완전히 숨은 프레임에서 정지하고, 1.5초 동안 손님이 사라진 뒤 남은 복귀를 재생한다. 공격 도중의 짧은 감지 누락으로 연기를 끊지 않는다.

실시간 합성은 새 영상 프레임 또는 새 카메라 프레임이 있을 때만 한다. 감지는 Worker 한 개, 입력 프레임 한 개만 사용한다. 화면을 떠나면 감지·카메라 트랙·영상 콜백·GPU 자원을 해제한다. 지원 브라우저에서는 화면 켜짐 유지를 요청한다.

실기기 확인: 이 페이지를 단독으로 열어 2시간 동안 평소·반응·숨기·복귀를 반복한다. 조절 화면의 **검사 숫자 저장**으로 JSON을 내려받는다. 카메라 사진이나 영상은 이 파일에 들어가지 않는다. 숨은 채 정지한 구간의 합성 FPS 0은 정상이며, 움직이는 구간의 영상 프레임 증가·디코딩 누락·오류·메모리 추세를 함께 확인한다. 실제 태블릿 측정 없이 PC 창 크기만 바꾼 결과를 태블릿 FPS로 쓰지 않는다.

현재 연기는 원본 눈 표면·고개·몸·도토리의 분리된 팔을 이용한다. 개별 업무의 긴 연기, 손과 소품의 정확한 접점, 이동 중 겹침은 고객용 채택 전에 영상으로 더 검토할 항목이다. 영상의 준비·공격 중에는 촬영된 동작을 재생하므로 매 프레임 손님 위치를 따라 새 동작을 만들지는 않는다.

자료 출처는 `ASSET-SOURCES.md`, 캐릭터 원본 해시는 `scene-metadata.json`을 본다. AI 영상 생성·유료 자산·카메라 저장·카메라 서버 전송은 사용하지 않는다.
